и объяснял концепции, я прогонял всё локально в WSL, читал каждую строку и проверял

## Как ставил задачи

Формат работы — итеративный, по шагам. Не просил «напиши всё приложение», а разбивал
на этапы: окружение → модели → схемы → роутеры → тесты → бонусы. На каждом шаге ассистент
давал код + объяснение, я проверял и только потом шёл дальше.

### Ключевой запрос №1 — старт проекта

> «Привет, дали такое тестовое [полный текст ТЗ], давай сделаем. Всё по шагам по порядку,
> начнём с создания папки проекта и создания репозитория на гитхаб, настройки окружения.
> У меня WSL. Чуть больше внимания удели для объяснения мне FastAPI, Pydantic v2.
> Начнём с проверки моего окружения.»

**Контекст:** полный текст ТЗ в первом сообщении (тарифы, промокод, рассрочка, статусы,
идемпотентность, HMAC).
**Что получил:** разбор концепций FastAPI/Pydantic v2 (v2-стиль `model_validator`,
`model_dump`, `ConfigDict`), проверку окружения, план проекта на 9 шагов.
**Что сделал сам:** прогнал проверки, зафиксировал зависимости в `requirements.txt`,
создал репозиторий через `gh repo create`.

### Ключевой запрос №2 — бизнес-логика расчёта рассрочки

> Попросил функцию, которая делит сумму на срок в копейках так, чтобы сумма всех платежей
> была **ровно равна** сумме к оплате, а лишние копейки уходили в первые платежи.
> Привёл пример из ТЗ: `1990000 / 3 → [663334, 663333, 663333]`.

**Что получил:** `base = amount // months`, `remainder = amount % months`,
`[base + 1] * remainder + [base] * (months - remainder)`.
**Как проверял:** написал параметризованный тест на 3/6/12 месяцев, который проверяет
`sum(schedule) == amount` — не только код ответа, но и **результат**.

### Ключевой запрос №3 — плоский JSON в 409

> «FastAPI оборачивает `HTTPException(status_code=409, detail={"error": "invalid_transition"})`
> в `{"detail": {...}}`, а ТЗ требует ровно `{"error": "invalid_transition"}`. Как вернуть
> плоский JSON?»

**Что получил:** ассистент подсказал `JSONResponse(status_code=409, content={"error": ...})`.
Это не очевидный момент — большинство туториалов используют `HTTPException`, и легко
пропустить требование ТЗ.

## Где модель ошибалась / что я правил

### 1. Конфликт Pydantic v2 с Python 3.14

Первая попытка поставить зависимости по старым пинам привела к несовместимости с Python 3.14.
Пришлось снимать старые пины и ставить свежие версии (`fastapi[standard]`, `pydantic[email]`,
`sqlalchemy`). Заметил по ошибке установки — ассистент не сразу учёл свежесть рантайма.

### 2. `status` как имя query-параметра перекрывало `fastapi.status`

В `list_payments` query-параметр назывался `status`, из-за чего внутри функции
«пропадал» модуль `fastapi.status` — потенциальная ловушка на будущее. Заметил при чтении
кода, переименовал в `payment_status` с `alias="status"` (URL остался прежним).

### 3. `.env.example` терялся из-за `.gitignore`

Файл `.env.example` подпадал под правило `.env.*` и не коммитился. Долго не мог понять,
почему `git ls-files` его не видит, пока не проверил `git check-ignore -v`.
Решение: добавил `!.env.example` (negation) в `.gitignore` и закоммитил.

### 4. Ruff падал в CI, но локально «почти» проходил

Четыре коммита подряд CI был красным — `I001 Import block is un-sorted` в
`app/routers/payments.py` (`Response, status, Query` вместо алфавитного порядка).
Локально я прогонял `ruff check .`, но фиксил импорты **позже**, чем коммитил. Собрал все
правки в один коммит `fix: ...` — CI позеленел. **Вывод:** нужно гонять
`ruff check . --fix` **до** коммита, а не после.
